## Patterns & Principles Earned

**Batch-then-tally discipline for worklists.** Each re-voice batch was committed, the drive_index entry removed in a separate commit, and the running tally updated before starting the next batch. This creates a recoverable checkpoint at every stage and makes partial completion visible in git history.

**Context launchers should be typed by task, not by project.** `task_session.py` encodes the insight that what you're *doing* (fixing, building, reviewing audio) determines what context is useful, not which project you're in. A git task in BDF and a git task in BRAIN_OS need the same git-oriented context slice.

**`id:` entries are canonical; `path:` borrowed-audio entries are technical debt.** Any topic that gets a dedicated narration should be converted to `id:` immediately, and the borrowed reference removed from the index. Letting path-format entries accumulate creates parity drift.

**Six small surgical fixes in one commit is acceptable when the fixes are truly independent and each is one-line.** The alternative — six separate commits for one-liners — creates log noise without adding traceability value.
