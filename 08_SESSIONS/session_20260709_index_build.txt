4. ARCHITECTURE DECIDED (three tiers, no duplication)
================================================================

00_INDEX\{Content,Business,Operations,Personal}.md   bucket -> projects
00_NAV\<Project>_Nav.md                              project -> internals
00_DASHBOARD\Navigation.md                           whole vault, auto-generated

DRY check that justified the new layer:
  00_NAV is one file per project (cardinality 1:1).
  00_INDEX is one file per bucket   (cardinality 1:many).
  Different cardinality = different job. Not a duplicate layer.

FINAL BUCKET MAPPING:

  CONTENT     soccer-content-generator (BDF)
              CA_Book  [rename pending]

  BUSINESS    CristianConstruction
              cc-landing            (sibling, not sub-item — separate deployable)

  OPERATIONS  BRAIN_OS
              C:\Knowledge          (canonical AI/TTS venv)
              obs-mcp-server
              resolve-mcp-server
              shared\brain-audio
              shared\book-compiler

  PERSONAL    read-along-app        (pre-revenue; graduation rule applies)
              instructor / teaching, guitar, learning logs

REASONING BEHIND THE NON-OBVIOUS PLACEMENTS:

  - BDF monetization stays in CONTENT, not BUSINESS. Its content pipeline IS
    its monetization engine. Splitting means every BDF session touches two
    buckets, which defeats routing. Also preserves identity priority:
    BUSINESS = income base (construction), CONTENT = passion (BDF).

  - Shared packages go to OPERATIONS. Assigning a shared component to one
    consumer's bucket misrepresents its blast radius.

  - read-along-app stays PERSONAL until first dollar or first external user
    commitment. Graduation is one line edited in two index files.

  - No fifth bucket for instructor work. A bucket with no filesystem footprint
    is maintenance cost, not structure.

KNOWN LIMIT: buckets route WHERE YOU SIT DOWN. They do not partition the
system. Session log 2026-06-17_2222_bdf_ca_brain_os_resolve.md is one session
across four projects and three buckets. If you ever expect buckets to tell you
what a change will break, they will lie. Nav files and the graph do that job.

8. INCIDENTAL MECHANICS LEARNED
================================================================

BOM         PowerShell 5.1 Set-Content / Out-File prepend EF BB BF.
            Editors hide it. Git sees it. Python json.load() chokes on it.
            WriteAllText(path, string) writes UTF-8 without BOM.
            Git normalizes line endings; it does NOT strip BOMs.

autocrlf    core.autocrlf=true means the working copy (CRLF) and the blob (LF)
            are not byte-identical. `git show HEAD:path` reads the blob;
            reading the file reads your disk. Different questions.

-replace    A REGEX operator, not literal. `ship\.` and `\[RESOLVED` had to be
            escaped. Unescaped, `.` matches any char and `[RESOLVED` is a
            character class. Use .Replace() for literal, surgical edits.

@' ... '@   An unterminated here-string leaves PowerShell at the >> prompt.
            Ctrl+C aborts. Paste multi-line blocks as ONE unit.

append      $existing + $new concatenates raw. If $existing lacks a trailing
            newline, entries fuse. Durable form:
              WriteAllText($path, $content.TrimEnd() + "`n")

Format-Hex  `-Count` does not exist in PowerShell 5.1 (added in 6+).

elevation   None of this needed Administrator. Writing files you own does not
            require elevation. Reflexive admin is a habit worth breaking.

`cd`        `git status` in C:\Dev\cc-landing reports on the wrong repo.
            Always cd C:\BRAIN_OS first.
