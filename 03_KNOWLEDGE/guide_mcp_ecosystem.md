# Guide: The MCP Ecosystem — Your AI Operating System

MCP stands for Model Context Protocol. It is the standard that allows Claude Code to connect to external tools and services. Without MCP, Claude Code can only read and write files and run terminal commands. With MCP, it can navigate your file system with structured awareness, read and write to your Obsidian vault, control DaVinci Resolve, manage OBS Studio, search documentation for any public library, and interact with Google Drive and Gmail. MCP turns Claude Code from a coding assistant into an operating system for your workflow.

Each MCP server is a separate process that Claude Code launches and communicates with through a defined protocol. You register servers with the claude mcp add command. The most critical flag is dash s user. Without it the server registers at project scope, meaning it only works in the directory where you ran the command. From any other project the server is invisible with no error message. Always use the user scope flag. Always.

My MCP ecosystem has six registered servers. Context7 is an HTTP server that provides documentation for any public library. You give it a library name, it resolves the correct documentation identifier, and returns current reference material. It cannot be populated with personal content. It is read-only for public libraries only. The filesystem server gives Claude Code structured visibility into four directories: C drive Dev, C drive BRAIN_OS, C drive Knowledge, and C drive Users titit Projects. The Obsidian server connects to the BRAIN_OS vault and provides eleven tools for reading, writing, and searching notes. The resolve MCP server has 52 tools for controlling DaVinci Resolve through a TCP bridge. The OBS server controls OBS Studio for streaming automation. The GitHub server provides pull request and issue management.

Each server uses one of two transport models. HTTP servers like Context7 and GitHub use remote endpoints with API key authentication. They are always available because they run in the cloud. Stdio servers like filesystem, Obsidian, and your custom MCP servers run as local processes on your machine. They start when Claude Code launches and stop when it closes.

Among stdio servers there are two connection behaviors. Eager servers attempt to reach their target application the moment they start. OBS is eager. If OBS is not running when Claude Code launches, the OBS server shows as Failed immediately. This is an honest signal. Lazy servers start their stdio process and show Connected without trying to reach their target. The Resolve server is lazy. It shows Connected even when DaVinci Resolve is not running. The TCP bridge to Resolve only activates when you call a tool. Understanding which servers are eager and which are lazy tells you how much to trust the Connected status for each one.

The three question framework for deciding when to use MCP is simple. First, does a connected MCP server handle this category of task? If yes, use it. Second, does the task require reading personal or company data? If yes, check internal tools before searching the web. Third, is this a task where the tool adds unique value that a direct file operation cannot provide? If no, skip the MCP and use the filesystem directly.

The MCP ecosystem required significant effort to build and has required maintenance between sessions. The filesystem server disappeared once and had to be restored. The Obsidian server was broken for two sessions before the vault name configuration was corrected. The Resolve server was completely unregistered despite having a functional implementation and had to be discovered and added manually.

The lesson from all of this is that the MCP ecosystem is infrastructure. It requires the same care as any other infrastructure: regular verification, documented configuration, and a recovery procedure for when things break. After every significant session, check that all servers show their expected status. After any configuration change, verify with an actual tool call before closing the session. The configuration lives in the claude dot json file at user scope. Keep a record of the registration commands so any server can be rebuilt from scratch in under two minutes.

When the ecosystem is fully operational it fundamentally changes how sessions run. Instead of spending the first ten minutes establishing context by dumping file contents, you load the project graph, verify the relevant MCP servers are responsive, and start working immediately. The AI has structural awareness of your entire ecosystem from the first message. That precision is what the MCP ecosystem is built to provide.
